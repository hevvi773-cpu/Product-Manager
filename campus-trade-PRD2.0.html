Part 1文档概述与项目背景

本文档覆盖平台所有已上线功能模块及核心业务规则，面向产品、开发、测试及运营人员。

1.1 文档说明

本文档为「校园二手交易平台」的产品需求文档，覆盖平台所有已上线功能模块及核心业务规则。V2.0 版本新增订单系统，实现从“信息展示”到“交易闭环”的升级，并保留 V1.0→V2.0 的迭代演进记录。

1.2 项目背景

1.2.1 为什么选择校园场景？

西南大学拥有五万余名在校同学，闲置物品流转需求体现在三方面：

  • 信任基础更深厚：用户均为同校同学，身份可追溯，比全开放平台信任起点更高。
  • 交易成本更低：无需物流体系，可约定校园内地点（宿舍楼下、食堂门口、教学楼前）面对面交接。
  • 需求集中且高频：开学季教材采购、毕业季清仓甩卖、期末季复习资料流转，形成明确交易波峰。

1.2.2 核心判断：身份校验是最大效率杠杆

做好“用户一定是本校在校学生”这一身份校验，是所有信任机制的基础。一旦发生纠纷或违规，平台可直接向学校相关部门上报，追溯到具体责任人。真实身份 + 可追责的闭环，使平台无需在虚假账号防控、复杂物流追踪、高强度信用累积上过度投入。

产品策略：先做优先级最高的核心功能，用身份校验替代泛化信用体系，不盲目堆砌功能。

1.2.3 V1.0 回顾与 V2.0 迭代动因

V1.0 成果：实现二手信息的结构化展示与状态透明化，验证了校园场景下轻量级信息聚合平台的可行性。用户经学号注册登录，可发布、浏览、线下交易、标记售出、评价，初步跑通交易闭环。

V1.0 遗留问题：

  • 交易状态依赖卖家单方面操作：卖家点击“标记已售出”时，系统不校验是否真有买家购买，也不记录买家身份。后果是已售出商品出现大量“无订单”记录，买家无法评价。
  • 买卖双方缺少明确确认机制：卖家可能忘记/延迟/不标记售出，平台无法知道交易是否真正完成。

V2.0 核心判断：用订单系统替代“卖家单方面标记售出”。所有交易必须经过“买家下单 → 卖家确认”流程才能完成，确保每笔售出都有买家记录可追溯、可评价。

1.3 产品定位

面向西南大学在校学生的校园内二手物品交易平台，支持出售与求购两类需求，提供从信息发布、浏览发现、下单购买、卖家确认到信用积累的完整交易闭环。平台定位为半封闭社区型交易工具，只有本校学生可注册使用，交易全部在线下完成，平台提供信息撮合、订单管理和信用背书，不介入资金流转和物流配送。

Part 3用户角色与典型场景

3.1 用户角色定义

👨‍🎓 学生用户

核心使用群体。学号即用户名，可发布、浏览、下单、管理订单、评价、查看消息、提交反馈。

🛡️ 管理员

运营方，独立后台入口，凭预设密码登录。负责审核、信用管理、反馈回复、数据监控，不参与交易。

👁️ 游客

未登录访问者，可浏览列表与详情，无法发布、下单或使用需认证的功能。

3.2 V2.0 新增典型场景

场景一：买家完整交易流程

  1. 进入商品详情页 → 点击「立即购买」。
  2. 填写联系方式（选填）和留言（选填）→ 提交创建订单，商品立即下架。
  3. 通过卖家联系方式约定线下见面交易。
  4. 卖家登录「我的订单」点击「确认」→ 订单 confirmed，系统将买家写入商品 buyer 字段。
  5. 买家在订单列表/详情页点击「评价」→ 一至五星 + 文字，自动更新卖家信用分。
  6. 确认前任一方取消 → 订单 cancelled，商品恢复在售。

场景二：卖家完整交易流程

  1. 商品审核通过后出现在首页。
  2. 买家下单 → 卖家在「我的订单」看到 pending 订单。
  3. 点击「确认」→ confirmed，买家被写入商品 buyer 字段，买家可评价。
  4. 若决定不出售 → 点击「取消」→ cancelled，商品恢复在售。

场景三：买家取消订单 & 场景四：评价流程

买家在 pending 状态订单点击「取消」→ cancelled，商品恢复在售，他人可再次下单。买家在卖家确认后，于已确认订单点击「评价」，提交后系统自动更新卖家信用分。

Part 5V2.0 新增功能详细说明

功能一：下单购买

功能描述：买家在商品详情页点击「立即购买」，填写联系方式（选填）和留言（选填），提交后系统创建订单（status=pending），商品 sold_status 立即变为 sold（下架），防止重复购买。

触发入口：商品详情页「立即购买」按钮 → POST /order/create

校验逻辑：

  • 用户是否已登录（未登录跳转登录页）
  • 商品状态是否为 approved 且 unsold
  • 当前用户不是卖家本人
  • 当前用户没有该商品的未取消订单

事务：① orders 表插入记录 status=pending；② products 表 sold_status=sold，sold_time=NOW()。

异常：未登录→跳转登录；已售出→弹窗“商品不可购买”；是卖家→“不能购买自己的商品”；已有未取消订单→“您已对该商品下过订单”。

功能二：我的订单列表

用户可在「我的订单」页面查看自己作为买家或卖家的所有订单，按创建时间倒序排列，展示商品名、价格、买家、卖家、状态、下单时间、联系方式、留言及差异化操作按钮。仅已登录学生用户可访问，已取消订单仍展示但不可操作，确认/取消需二次弹窗。

订单状态用户角色显示按钮
pending卖家✅ 确认 ｜ ❌ 取消
pending买家❌ 取消订单
confirmed买家⭐ 评价
confirmed卖家无
cancelled任意无

功能三：卖家确认订单

卖家在「我的订单」点击「确认」→ 二次确认弹窗 → 事务：① orders.status=confirmed；② products.buyer=买家用户名。确认后买家获得评价权限。仅订单对应卖家、且订单状态为 pending 时可执行；buyer 写入不可撤销。

功能四：取消订单

买家与卖家均可在 pending 时取消。事务：① orders.status=cancelled；② products.sold_status=unsold，sold_time=NULL。取消后商品恢复在售，不可恢复。

功能五：信用评价（V2.0 权限升级）

评价权限：仅 confirmed 订单的买家可评价（V1.0 为“商品 sold 即可评”，无法校验真实购买）。兼容旧数据：V1.0 已售且无订单的商品，保留“卖家手动标记 sold 且当前用户是卖家本人”的评价权限。

评价权限校验逻辑：
1. 查询 orders：product_id 匹配 且 buyer=当前用户 且 status=confirmed → 允许评价
2. 否则检查 V1.0 旧数据（sold 且当前用户是卖家本人）→ 允许
3. 均不满足 → “您尚未完成该商品的交易，无法评价”

信用分计算规则：

平均分 = Σ评分 ÷ 评价总数（无评价默认 100 分）
基础分 = 平均分 × 20
数量奖励 = MIN(评价总数 × 2, 15)
差评惩罚 = 1星数 × 5 + 2星数 × 2
信用分 = MAX(基础分 + 数量奖励 − 差评惩罚, 0)

A120–149信用优秀✅#0d6efd
B80–119信用良好👍#198754

功能六：导航栏入口（新增）

Part 7非功能需求

⚡ 性能

  • 首页加载 ≤ 3 秒（2核2GB）
  • 订单列表接口 ≤ 500ms
  • 下单操作 ≤ 1 秒
  • 支持 50–100 人同时在线

🔒 安全

  • Flask session 管理登录态
  • 学号前后端双重校验
  • 订单操作校验当事人，后台 admin_required
  • 参数化查询防 SQL 注入
  • 图片指定格式，单张 ≤ 5MB

🔄 数据一致性

  • 下单 + 下架 同一事务
  • 确认 + buyer 写入 同一事务
  • 取消 + 恢复在售 同一事务
  • 信用分更新使用事务

🛡️ 可靠性 & 扩展性

  • 每日 2:00 备份，保留 7 天
  • systemd 开机自启、异常重启
  • 待审核超 24h 自动通过
  • 预留日志表、可平滑升级 bcrypt、图片可迁对象存储
